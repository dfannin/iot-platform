# Shared Grafana alerting (host-wide)

These files are **not specific to router-monitor**. They set up Grafana alerting
for every project on this Grafana server (design §5.6):

| File | Installed as | Contents |
|---|---|---|
| `alerting/shared-alerting.json` | `/etc/grafana/provisioning/alerting/shared-alerting.json` | Slack contact point `slack-alerts`, message template, the notification policy tree |
| `grafana-server.service.d/alerting.conf` | `/etc/systemd/system/grafana-server.service.d/alerting.conf` | Passes the webhook URL to Grafana as `SLACK_ALERTS_WEBHOOK_URL` |

They live in this repository until a second project adds alerts; then they move to a
small host-configuration repository of their own. The JSON is generated by
`tools/build_alerting.py` (`--check` verifies it).

## Rules for every project

- **Only this file defines notification policies.** Grafana has one policy tree per
  organisation, and a provisioning file with `policies` replaces the whole tree. A
  project ships rule files only (`groups:`), in its own folder.
- **Every rule carries the labels** `project` (for example `router-monitor`,
  `esp-shed`) and `severity` (`critical`, `warning` or `info`), and the annotations
  `summary` and `description`, which the shared template shows. The tree routes on
  labels, so a new rule needs no policy change. To send some alerts elsewhere, add a
  nested route with a matcher on `project` or `severity` here.
- **No secrets in provisioning files.** The webhook URL comes from the environment.
- Provisioned resources cannot be edited in the Grafana UI; change the generator and
  reinstall.

## Install (once, on the Grafana server)

Before the first install, look at Alerting → Notification policies and Contact points
in Grafana. Anything made there by hand is replaced by this file's policy tree.

1. The secrets file must be in `KEY=value` form for systemd. If it holds only the URL,
   add the key in front (this changes the content, not the name):

   ```bash
   F=/etc/grafana/secrets/slack-webhook-router-monitor
   sudo grep -q '^SLACK_ALERTS_WEBHOOK_URL=' "$F" || sudo sed -i '1s|^|SLACK_ALERTS_WEBHOOK_URL=|' "$F"
   sudo chown root:root "$F" && sudo chmod 600 "$F"
   sudo cut -c1-49 "$F"    # shows the key and the start of the URL only
   ```

   To send a test message by hand from now on:

   ```bash
   sudo sh -c '. /etc/grafana/secrets/slack-webhook-router-monitor; curl -sS -X POST \
     -H "Content-type: application/json" --data "{\"text\":\"test from Grafana host\"}" \
     "$SLACK_ALERTS_WEBHOOK_URL"'
   ```

2. Install the drop-in and the shared provisioning file, with Grafana restarted:

   ```bash
   sudo deploy/install.sh --shared-alerting
   ```

3. Check: `journalctl -u grafana-server --since "5 min ago" | grep -i -E "provision|alert" | grep -i -E "error|fail"`
   prints nothing; Alerting → Contact points shows `slack-alerts`; its **Test** button
   posts a message to the channel; Notification policies shows the default policy
   sending to `slack-alerts`.

Then install each project's rule file (router-monitor: `deploy/grafana/README.md`).
